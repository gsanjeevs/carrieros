🚗 Solo Mode (default)
When an owner hasn't added any drivers, they operate in Solo mode. They see the full Owner UI but also have Driver-level actions available (update status, DVIR). No role switching needed — it's a single unified view. Solo mode unlocks Team management the moment a first driver is invited.
💰 Why Drivers Can't See Rates
Carriers are sensitive about what they charge customers. A driver knowing the load rate creates negotiation leverage and competitive risk. Rate and invoice data is excluded from all driver-visible API responses — not just hidden in the UI.
📋 Dispatcher vs Finance
These two roles are intentionally non-overlapping: a Dispatcher can see all operational data but zero financial data; Finance can see all financial data but zero operational dispatch data. The Owner is the only role that spans both. Neither role can invite team members or change the subscription.
⏫ Tier Gating
Dispatcher and Finance roles require Growth plan or above ($79/mo+). Attempting to invite someone to these roles on a Starter plan shows an upgrade prompt. The role options are visible but disabled with a lock icon and "Upgrade to Growth" CTA.
🔗 Driver Accounts
Drivers create accounts via an invite link (SMS or email). They are subordinate to the carrier's account — no plan selection, no billing, no CC. If the carrier's subscription lapses, driver access is suspended. If the carrier removes a driver, the driver's app account is immediately deactivated.
📱 Driver Tab Bar
The driver tab bar only shows: My Load, DVIR, History, Profile. The full owner tab bar (Loads, Dispatch, Invoice, Team, Settings) is never rendered for driver accounts. Role is checked server-side on every authenticated request, not just on login.
🛡️ Implementation: Supabase RLS
Permissions must be enforced at the database layer via Row Level Security, not just the frontend UI. Key tables:

• user_roles — (user_id, company_id, role ENUM) — source of truth for all permission checks
• loads — drivers can only SELECT rows where assigned_driver_id = auth.uid()
• invoices — RLS policy: role IN ('owner', 'finance') only
• loads.rate — column-level: excluded from driver queries via a loads_driver_view view that omits rate columns
• company_members — only owners can INSERT/DELETE (invite & remove team members)

Never trust the client for role enforcement. All role checks should be re-verified server-side. Frontend visibility is UX only.
