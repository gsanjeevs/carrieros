Developer Notes — Mockup 19

DB Schema

Table: driver_messages (tech-spec.md §15). Columns: id, company_id, load_id (FK — required, NOT nullable), sender_id (profiles.id), body, sent_at, read_at (null = unread).


Messages are scoped per load. A driver can only read messages for their assigned load. Dispatcher can read all messages for their company's loads. No global inbox table needed — query by load_id.

Realtime & Unread

Use Supabase Realtime (supabase.channel()) to subscribe to new messages on the current load's thread. Push notification badge count: SELECT COUNT(*) FROM driver_messages WHERE load_id = ? AND read_at IS NULL AND sender_id != auth.uid().


Mark read: UPDATE read_at = now() when user opens the chat thread. Driver sees "2 new" badge on load card. Dispatcher sees unread count on Messages tab icon.

RLS & Routes

  • Driver: read/write on messages for assigned load only
  • Dispatcher: read/write on all company load messages
  • Owner/Solo: same as Dispatcher
  • Finance: no access to driver_messages

Route: /my-loads/[id]/chat (driver), /dispatch/messages (dispatcher). System message for load status changes: INSERT a driver_messages row with sender_id = null and body = "Load status updated to Delivered" — rendered differently in UI (see sys-msg style).
