Developer Notes — Mockup 20

GPS Logging Architecture

Table: ifta_state_crossings (tech-spec.md §15). Columns: truck_id, driver_id, load_id, state, crossed_at, lat, lng, odometer_est, source (enum: 'gps' | 'manual').


GPS polling: @capacitor/geolocation watchPosition() every 15 min (Growth only). On state boundary detection (reverse geocode lat/lng to state), INSERT a new crossing row. Stop polling when load status = delivered. Battery impact: low — 15-min interval, no continuous tracking.


iOS note: Background location requires NSLocationAlwaysUsageDescription + user must select "Always Allow" in Settings. Default "While Using" permission → GPS stops when app backgrounds. Show a one-time prompt at Growth activation explaining why Always Allow is needed for IFTA accuracy.

GPS Completeness Check + Fallback Trigger

On load delivery, run a completeness check before marking delivered:

  • Fetch all ifta_state_crossings for this load
  • Sum odometer_est across rows
  • Compare to load's total_miles field
  • If sum < 60% of total_miles → show Screen 4 (odometer fallback)
  • If sum ≥ 60% → GPS acceptable → proceed to delivery

Manual entries: INSERT rows with source = 'manual', no lat/lng. If manual rows saved for a load, DELETE all source = 'gps' rows for that load — manual overrides GPS entirely, no mixing. Pre-fill GPS-logged state values so driver only corrects what's wrong.

IFTA Summary View & Tiers

Growth: Show miles by state (aggregate of ifta_state_crossings). No tax calculation. Query: GROUP BY state SUM(odometer_est) per quarter window. Flag loads where source = 'manual' with a ✎ indicator so owner knows GPS didn't capture it.


Pro: Full IFTA tax hub (mockup-17). Join fuel_stops on state + quarter. Apply formula: (miles_state / total_miles × total_fuel × state_rate) − fuel_purchased_state × state_rate. Tax rates table: ifta_tax_rates(state, quarter, rate_per_gallon) — seed from IFTA published rates quarterly.
